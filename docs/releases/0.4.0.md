# KubeWeasel 0.4.0

Applications can now have multiple domains: keep a public hostname and an internal hostname together using the same Traefik controller and application Service.

- Add, edit and remove individual entries in Application → Networking → Domains.
- Set each hostname's path, ingress class and HTTPS policy independently.
- Choose a saved domain for networking diagnostics and connection tests.
- Inspect certificate status for the selected domain; automatic certificates use independent Secrets.
- Preserve existing single-domain Ingress names and TLS settings during upgrade. Adding or removing other domains leaves the existing route and application workload intact.
- Removing a route retains certificate resources, Secrets, application data and other domains.

Internal DNS must resolve to a private ingress address accessible to your clients. DNS names do not enforce network isolation; use VPN or network policies. Cloudflare Tunnel can terminate public HTTPS while forwarding HTTP to Traefik. No second ingress controller is needed.

Upgrade with the versioned installer; owner data, cluster keys and saved private dashboard access are retained. Existing remote connections need the updated namespace Role from `deploy/remote-cluster-rbac.yaml`, which adds Ingress list permission. The local Helm Role is updated automatically. Secret read access is not added.

The existing `/domain` endpoint remains compatible and controls the legacy route. New routes are independent resources, with a limit of 20 per application. Account-volume permission recovery from v0.3.1 remains included.
