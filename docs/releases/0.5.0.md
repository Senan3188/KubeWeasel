# KubeWeasel 0.5.0

Connect applications to several databases, Kafka brokers and custom services using named, project-scoped connections backed by Kubernetes Secrets.

- Define PostgreSQL, MySQL, Redis, Kafka or custom connections with user-chosen names, including several of the same type.
- Share connections with selected applications in their project and map keys to each backend's environment variable names.
- Keep saved values hidden. Replace selected keys without overwriting unchanged credentials or external Secret/ConfigMap references.
- See which apps use a connection and which need a restart after values change. Distinguish requested restarts from current ready rollouts; failed restarts retain their warnings.
- Retain Secrets on detach and prevent deleting connections still referenced by workloads or Pods. Moving an app between projects requires detaching its connection variables first.
- Keep existing domains, workloads, account storage, cluster keys and persistent volumes during upgrade.

## Upgrade and permissions

Back up the account database and matching cluster key together, and back up application data and Kubernetes Secrets independently. Use the v0.5.0 installer with `upgrade`; do not delete the account PVC.

**Namespace permissions expand in this release.** The local Helm Role and example remote namespace Role add Secret `get`, `list`, `update`, and `delete` alongside existing create permission. Kubernetes RBAC cannot restrict these verbs by label: the dashboard service account can access all Secrets in its application namespace. The app only exposes connection metadata and never returns stored values. Review this permission scope and use a dedicated namespace. List access to ReplicaSets, DaemonSets and CronJobs supports conservative deletion checks; no cluster-admin or node permission is added.

Helm applies local permissions during upgrade. For remote connections, reapply `deploy/remote-cluster-rbac.yaml` in each remote application namespace. Other app features remain usable with older credentials; missing connection permissions are reported explicitly.

Connections save configuration; they do not deploy or initialize databases/Kafka, change database-side passwords, configure backups, or enable Kubernetes encryption at rest. Rotation requires coordinating the actual database credentials and explicitly restarting consumers. Project folders are not Kubernetes isolation boundaries. See [connections and secrets](../connections.md).

The repository also includes the optional, separately installed NetBird/K3s ingress host helper and its isolated packet tests. It is not automatically installed by Helm and is not required on unaffected networks.
