# KubeWeasel 0.2.0

Manage multiple Kubernetes environments and administer their nodes from one dashboard.

## New features

- Connect clusters through self-contained kubeconfig files, select a cluster in the sidebar, test API connectivity and permissions, rename connections, rotate credentials, and disconnect without deleting remote workloads or volumes.
- Keep projects, applications, settings, port forwards, monitoring and build/rollout workers scoped to their connection. Existing projects remain under Local cluster with their original IDs.
- Encrypt saved cluster credentials with AES-256-GCM. Uploaded configurations reject executable authentication plugins, file references, impersonation, proxy URLs and disabled TLS verification.
- Inspect node health, CPU/memory usage, machine details, labels, taints, pods and events. Cordon/uncordon, edit custom labels/taints and preview drains when the connection has the required permissions.
- Drain through typed policy/v1 evictions with node/pod identity preconditions, disruption-budget enforcement and bounded partial-result reporting. Local/ephemeral data, unmanaged pods and unverifiable controllers block drains; there is no force-delete option.
- Generate private, expiring, namespace-limited connection files with the included helper, and grant optional read-only discovery or node-management permissions using separate manifests.

## Install or upgrade

Download `install.sh` from this release. It requires kubectl, Helm 3.12+ (or Helm 4), a running cluster and persistent storage.

```sh
bash install.sh install --version 0.2.0 --context YOUR_CONTEXT --namespace kubeweasel
# Existing installation:
bash install.sh upgrade --version 0.2.0 --context YOUR_CONTEXT --namespace kubeweasel
```

The release includes a Helm chart, installer, SHA-256 checksums and public Linux AMD64/ARM64 images at `ghcr.io/senan3188/kubeweasel:0.2.0`. The installer verifies the chart checksum and leaves failed installations inspectable. Dashboard access remains local through port-forwarding unless an administrator configures an HTTPS reverse proxy.

Node mutation permissions are disabled by default. An administrator may enable `nodeManagement=true` in Helm; the controls affect workloads across all namespaces. Namespace-only installer mode disables these permissions. Read-only monitoring remains separately configurable.

## Upgrade and backup notes

- Back up the account SQLite database before upgrading. Use SQLite-aware backup tooling or stop the dashboard; copying only the main database during active WAL writes is not sufficient.
- The project schema migration preserves existing IDs and assigns old folders to the local connection. Do not downgrade a migrated database to v0.1.0; restore the pre-upgrade backup if rolling back.
- Remote connection encryption creates `/data/kubeweasel.db.cluster-key` beside the default account database. Preserve the account volume and back up the database and matching private key together. Missing/wrong keys fail closed instead of replacing credentials.
- Disconnect retains remote applications, namespaces and data volumes. Old folder metadata remains in dashboard storage, but a newly added connection gets a new ID and does not automatically recover that folder organization.
- One owner has full dashboard access to all configured connections. This release does not add teams, project-level permissions, private Git access or automatic deployment webhooks.

## Verification

Rust tests cover authentication, cluster isolation, legacy migration, encrypted credential persistence, safe node patches, disruption-budget refusals and completed/blocked drains. Installer/helper checks and Helm permission variants run in CI. Cluster lifecycle and namespace-limited deployment checks were exercised in Docker Desktop; node mutation safety was tested with a simulated Kubernetes API, with real-node inspection/preview and desktop/mobile UI checks.
