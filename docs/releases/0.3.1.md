# KubeWeasel 0.3.1

Fixes dashboard startup after an account-volume remount adds group permissions to the saved cluster key. This could cause `Cluster key file must be private (chmod 600)` and leave the dashboard restarting indefinitely.

A non-root init container now restores mode 0600 on the existing key after mounting the account volume, before the dashboard starts. It does not read, replace or regenerate the key. Strict runtime validation remains enabled, and symbolic-link keys are rejected.

Upgrade with installer v0.3.1. Existing owners, projects, encrypted cluster connections and deployed applications are preserved; reinstall or account-volume deletion is not required. The same repair runs on future Pod starts.

Private dashboard access introduced in v0.3.0 remains available:

```sh
bash install.sh upgrade \
  --private-http http://deploy.example.internal:7878 \
  --listen-address 100.73.28.50
```

Keep database-plus-cluster-key backups together. Uninstall retains the account PVC and application workloads. Deleting the account PVC is an explicit account reset that permanently removes the owner, project folders and saved cluster credentials; it does not remove deployed application workloads or their volumes.
